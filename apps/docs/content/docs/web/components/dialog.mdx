Use it for a short task that is done away from the page and then put away: renaming something, inviting people, filling in a few fields.

The task sits in a panel, and `Dialog.Footer` moves out of the panel into the darker band underneath, where its buttons are equal pills. `variant="plain"` is a single surface with the footer ruled off at its foot, for a dense form. A press outside, Escape or the close button in the corner dismiss it.

The dialog is never taller than the screen: the header and footer stay put and `Dialog.Body` scrolls between them. On a screen under 640px wide it rests at the bottom, where a thumb reaches its buttons.

For a yes-or-no question, use [Alert Dialog](/docs/web/components/alert-dialog). For a longer task that keeps the page in view, use [Sheet](/docs/web/components/sheet).

## Composition

```tsx
<Dialog>
  <Dialog.Trigger />
  <Dialog.Content>
    <Dialog.Header>
      <Dialog.Title />
      <Dialog.Description />
    </Dialog.Header>
    <Dialog.Body>
      <Dialog.List>
        <Dialog.ListGroup>
          <Dialog.ListItem />
        </Dialog.ListGroup>
      </Dialog.List>
    </Dialog.Body>
    <Dialog.Footer>
      <Dialog.Close />
    </Dialog.Footer>
  </Dialog.Content>
</Dialog>
```

- **`Dialog.Trigger`** — What opens the dialog. Pass your own button as `render`.
- **`Dialog.Content`** — The dialog, over a dimmed page. `variant` is `inset` (a panel in a band) or `plain` (one surface), `size` is `sm`, `md` or `lg`, `showClose` draws the round close button, and `blur` frosts the page behind it.
- **`Dialog.Header`** — The title and the line under it, given as `title` and `description` or as parts. It leaves room for the close button. Anything else in it, such as a search field, stays put while the body scrolls.
- **`Dialog.Title`** — The dialog's name. It is announced when the dialog opens.
- **`Dialog.Description`** — A sentence under the title, read out after it.
- **`Dialog.Body`** — The part that scrolls, with a thin drawn thumb. Its children are laid out in a column with a gap, so the fields of a form need no wrapper. A hairline appears under the header once its content has scrolled.
- **`Dialog.List`** — A list of one-line choices, such as time zones or the projects to move something to. The arrow keys, Home and End move between its items, and it opens scrolled to the selected one.
- **`Dialog.ListGroup`** — A run of items under a `label`, which stays pinned at the top while its items scroll under it.
- **`Dialog.ListItem`** — One choice. `selected` tints and checks it, `onSelect` is called when it is pressed or chosen with Enter, and `meta` puts quieter text at its end in figures that line up.
- **`Dialog.Footer`** — The buttons. In the inset look they sit in the band as equal pills; in `plain` they sit at the end of a ruled strip. Keep it a direct child of `Dialog.Content`.
- **`Dialog.Close`** — Closes the dialog. Pass your own button as `render`, such as Cancel.

## Examples

### Inviting people

A field, a role [Select](/docs/web/components/select) and an Add button in one row, over the list of people invited so far. Pressing Enter in the field adds the address.

<ComponentPreview name="dialog/invite" height={180}>

```tsx lineNumbers
'use client';

import { Avatar } from '@/components/panelui/avatar';
import { Button } from '@/components/panelui/button';
import { Dialog } from '@/components/panelui/dialog';
import { Frame } from '@/components/panelui/frame';
import { Input } from '@/components/panelui/input';
import { Select } from '@/components/panelui/select';
import { useState } from 'react';

const ROLES = [
  { value: 'editor', label: 'Editor' },
  { value: 'viewer', label: 'Viewer' },
];

type Invite = { email: string; role: string };

export default function DialogInvite() {
  const [invites, setInvites] = useState<Invite[]>([
    { email: 'ines@quarry.dev', role: 'editor' },
    { email: 'tomas@quarry.dev', role: 'viewer' },
  ]);
  const [email, setEmail] = useState('');
  const [role, setRole] = useState('editor');

  const add = () => {
    const next = email.trim();
    if (!next.includes('@') || invites.some((invite) => invite.email === next)) return;
    setInvites([...invites, { email: next, role }]);
    setEmail('');
  };

  return (
    <Dialog>
      <Dialog.Trigger render={<Button />}>Invite people</Dialog.Trigger>
      <Dialog.Content>
        <Dialog.Header title="Invite to Quarry" description="They get an email with a link to join." />
        <Dialog.Body>
          <form
            className="flex gap-2"
            onSubmit={(event) => {
              event.preventDefault();
              add();
            }}
          >
            <Input
              type="email"
              placeholder="name@company.com"
              aria-label="Email address"
              value={email}
              onChange={(event) => setEmail(event.target.value)}
              className="min-w-0 flex-1"
            />
            <Select items={ROLES} value={role} onValueChange={(value) => setRole(value as string)}>
              <Select.Trigger aria-label="Role" className="w-28">
                <Select.Value />
              </Select.Trigger>
              <Select.Content>
                {ROLES.map((item) => (
                  <Select.Item key={item.value} value={item.value}>
                    {item.label}
                  </Select.Item>
                ))}
              </Select.Content>
            </Select>
            <Button type="submit" variant="outline">
              Add
            </Button>
          </form>
          <Frame variant="plain">
            <Frame.Panel>
              {invites.map((invite) => (
                <Frame.Row key={invite.email}>
                  <Frame.Media>
                    <Avatar name={invite.email} size="sm" />
                  </Frame.Media>
                  <Frame.Content>
                    <Frame.Title as="p">{invite.email}</Frame.Title>
                  </Frame.Content>
                  <Frame.Actions>
                    <Frame.Description>{invite.role === 'editor' ? 'Editor' : 'Viewer'}</Frame.Description>
                  </Frame.Actions>
                </Frame.Row>
              ))}
            </Frame.Panel>
          </Frame>
        </Dialog.Body>
        <Dialog.Footer>
          <Dialog.Close render={<Button variant="secondary" />}>Cancel</Dialog.Close>
          <Dialog.Close render={<Button />}>
            Send {invites.length} {invites.length === 1 ? 'invite' : 'invites'}
          </Dialog.Close>
        </Dialog.Footer>
      </Dialog.Content>
    </Dialog>
  );
}
```

### A form

A name, an address with a fixed prefix in an `Input.Group`, a [Textarea](/docs/web/components/textarea) and a [Select](/docs/web/components/select). The form lives in the body and the submit button in the footer, joined by the form's `id`. An empty name marks its [Label](/docs/web/components/label) invalid; Create shows a spinner while it saves. `dismissible={false}` keeps a stray press outside from throwing the form away.

### Choosing from a long list

`Dialog.List` holds the cities in `Dialog.ListGroup`s by region, whose headings stay pinned as the list scrolls, and each `Dialog.ListItem` shows the time there now and its offset as `meta`. The search field in the header stays put. Down moves from the field into the list, Enter in the field takes the first city found, and choosing one closes the dialog, so it draws no close button: `showClose={false}`.

<ComponentPreview name="dialog/scroll" height={180}>

```tsx lineNumbers

import { Button } from '@/components/panelui/button';
import { Dialog } from '@/components/panelui/dialog';
import { Input } from '@/components/panelui/input';
import { useEffect, useState, type KeyboardEvent } from 'react';

const REGIONS: { name: string; zones: [string, string][] }[] = [

      ['Asia/Tokyo', 'Tokyo'],
    ],
  },
  {
    name: 'Oceania',
    zones: [
      ['Pacific/Honolulu', 'Honolulu'],
      ['Australia/Perth', 'Perth'],
      ['Australia/Sydney', 'Sydney'],
      ['Pacific/Auckland', 'Auckland'],
    ],
  },
];

const CITY = Object.fromEntries(REGIONS.flatMap((region) => region.zones));

/** The time there now, and its offset from UTC, as the browser knows them today. */
function clock(zone: string, now: Date) {
  const time = new Intl.DateTimeFormat('en-GB', { timeZone: zone, hour: '2-digit', minute: '2-digit' }).format(now);
  const name = new Intl.DateTimeFormat('en-US', { timeZone: zone, timeZoneName: 'shortOffset' })
    .formatToParts(now)
    .find((part) => part.type === 'timeZoneName')?.value;
  const offset = (name ?? 'GMT').replace('GMT', 'UTC').replace('-', '−');
  return `${time} · ${offset}`;
}

export default function DialogScroll() {
  const [open, setOpen] = useState(false);
  const [zone, setZone] = useState('Europe/Istanbul');
  const [query, setQuery] = useState('');
  const [now, setNow] = useState(() => new Date());

  // The times move on while the list is open.
  useEffect(() => {
    if (!open) return;
    setNow(new Date());
    const timer = window.setInterval(() => setNow(new Date()), 15000);
    return () => window.clearInterval(timer);
  }, [open]);

  const needle = query.trim().toLowerCase();
  const regions = REGIONS.map((region) => ({
    ...region,
    zones: region.zones.filter(([, city]) => city.toLowerCase().includes(needle)),
  })).filter((region) => region.zones.length > 0);

  const choose = (next: string) => {
    setZone(next);
    setOpen(false);
  };

  // Down from the field goes into the list; Enter takes the first city found.
  const fromSearch = (event: KeyboardEvent<HTMLInputElement>) => {
    if (event.key === 'ArrowDown') {
      event.preventDefault();
      document.querySelector<HTMLElement>('[data-slot=dialog-list-item]')?.focus();
    }
    if (event.key === 'Enter' && regions[0]) choose(regions[0].zones[0][0]);
  };

  return (
    <Dialog
      open={open}
      onOpenChange={(next) => {
        setOpen(next);
        if (!next) setQuery('');
      }}
    >
      <Dialog.Trigger render={<Button variant="outline" />}>Time zone: {CITY[zone]}</Dialog.Trigger>
      <Dialog.Content size="sm" showClose={false} className="h-[32rem]">
        <Dialog.Header title="Time zone" description="Meetings are shown in it.">
          <Input.Group className="mt-3">
            <Input.Addon>
              <SearchIcon />
            </Input.Addon>
            <Input
              type="search"
              placeholder="Search cities"
              aria-label="Search cities"
              value={query}
              onChange={(event) => setQuery(event.target.value)}
              onKeyDown={fromSearch}
            />
          </Input.Group>
        </Dialog.Header>
        <Dialog.Body>
          {regions.length > 0 ? (
            <Dialog.List aria-label="Time zones">
              {regions.map((region) => (
                <Dialog.ListGroup key={region.name} label={region.name}>
                  {region.zones.map(([id, city]) => (
                    <Dialog.ListItem key={id} selected={id === zone} meta={clock(id, now)} onSelect={() => choose(id)}>
                      {city}
                    </Dialog.ListItem>
                  ))}
                </Dialog.ListGroup>
              ))}
            </Dialog.List>
          ) : (
            <p className="py-10 text-center text-sm text-muted-foreground">No city matches “{query.trim()}”.</p>
          )}
        </Dialog.Body>
      </Dialog.Content>
    </Dialog>
  );
}
```

```tsx lineNumbers
            <Input id="profile-email" value={email} readOnly />
          </div>
        </Dialog.Body>
        <Dialog.Footer>
          <Dialog.Close render={<Button variant="secondary" />}>Cancel</Dialog.Close>
          <Dialog.Close render={<Button />}>Save profile</Dialog.Close>
        </Dialog.Footer>
      </Dialog.Content>
    </Dialog>
  );
}
```

## Notes

### Closing

A press outside, Escape and the close button close it, and so does any `Dialog.Close`. `dismissible={false}` stops a press outside from closing it, for a form whose changes would be lost; Escape still works. Hold `open` yourself with `onOpenChange` to close it from code, for example once a form has saved.

### Focus

When it opens, focus goes to the first field in it. The close button is drawn in the corner but comes last in the order, so the way out is not the first thing focused. Focus returns to the trigger when it closes.

### Forms

Put the `<form>` in `Dialog.Body` with an `id`, and give the submit button in the footer `type="submit"` and `form` set to that `id`. Enter in a field then submits it, and the footer can stay a direct child of the content.

### On a phone

Under 640px wide the dialog sits at the bottom of the screen, 8px clear of the edges, and can be as tall as the screen less that gap.

### Server Components

`Dialog` is a client component. In a file that starts with `"use client"`, write its parts with a dot, as on this page. A Server Component cannot read `Dialog.Trigger` off the import, so each part is also exported by name: `DialogTrigger` is `Dialog.Trigger`, and so on for the others.

```tsx
import { Dialog, DialogTrigger, DialogContent, DialogHeader, DialogTitle, DialogDescription, DialogBody, DialogFooter, DialogClose, DialogList, DialogListGroup, DialogListItem } from "@/components/panelui/dialog"
```
